# Crucible v1.0.0 — Release Report

**Date:** 2026-08-06 · **License:** Apache-2.0 · **Scope:** first tagged release

This report states only what is measurable in this repository. Where a claim
rests on an artifact, the artifact is named so you can reproduce it. Numbers
from the model/executor are from **synthetic** fixtures on a small suite, with
their sample size — they demonstrate the *method*, not a production benchmark.

## 1. What shipped

Crucible v1.0.0 is a multi-tenant, API-first platform that evaluates and
operates one bounded workload: a data-analysis agent answering questions over
uploaded CSV/Parquet datasets with constrained Python execution. Phases 0–10 of
the implementation plan are complete:

## 2. Measured evidence

### 2.1 Automated tests

Full suite run for this report against the live local stack (Docker 29.6.1;
Postgres + Redis + MinIO via `docker compose`; the built
`crucible-sandbox-runner:local` image). **370 tests collected; 369 passed, 1
skipped, 0 failed.**

| Selection | Command | Result |
|---|---|---|
| Non-integration (incl. sandbox canaries) | `pytest -m "not integration"` | 291 passed, 1 skipped, 78 deselected |
| Integration | `pytest -m integration` | 78 passed |
| Sandbox containment canaries | `pytest -m sandbox` | 26 passed |
| Security (`tests/security/`, marked `integration`) | `pytest tests/security` | 31 passed |

- The single skip is platform-specific: `tests/unit/test_execution_parser.py`
  ("POSIX symlink semantics") is skipped on Windows.
- There is no `security` pytest marker; the security tests are marked
  `integration` and live in `tests/security/` (so they run within the 78
  integration tests and can be selected by path).
- **2 Playwright** web end-to-end specs (`apps/web/e2e/`).
- **Clean-clone reproduction:** a fresh `git clone` + `uv sync --dev` in an
  isolated environment succeeded (exit 0); `ruff format --check`, the seed-suite
  reference calculators, and `pytest tests/unit` (265 passed, 1 skipped) all
  passed from the clean checkout.

### 2.2 Offline correctness — regression gate

From the committed report [`evals/reports/examples/core-comparison.json`](../../evals/reports/examples/core-comparison.json)
(`content_sha256` `15f35d7c…`, `git_sha` `f0bbbd5`, scorer `1.0.0`):

| Field | Value |
|---|---|
| Suite | `core` v1.0.0, hash `9bd412a4…` |
| Cases | 16 |
| Gate status | **pass** |
| Paired delta | 0.0 (CI `[0.0, 0.0]`, tolerance 0.02) |
| Correctness regressions | none |
| Policy regressions | none |

Re-run for this release through the Docker sandbox (`make eval-run`), the gate
reproduced identically: `gate=pass delta=0.0 ci=[0.0, 0.0] accuracy=1.0`.

The gate blocks a material regression (upper CI bound below tolerance) or any
policy failure. Building the harness surfaced two genuine agent bugs (fixed),
and a deliberately injected regression is blocked end-to-end through the real
sandbox — see [docs/evaluation/metric-contract.md](../evaluation/metric-contract.md).

### 2.3 Efficiency — routing experiment

From [`evals/reports/examples/router-comparison.json`](../../evals/reports/examples/router-comparison.json)
(`executor_backend: docker`). **Prices are synthetic** — the `fake` provider's
registry prices exercise the accounting pipeline, not a market rate; escalated
calls include the burned tier-1 cost.

| Policy | Accuracy | Answered / Abstained | Total cost (USD, synthetic) | p95 latency | Escalations |
|---|---|---|---|---|---|
| `default` (single-tier@1) | 1.0 | 13 / 3 | 0.004724 | 1046 ms | 0 |
| `routed` (two-tier@1) | 1.0 | 13 / 3 | 0.001745 | 641 ms | 11 |

Identical accuracy (1.0) at **63% lower synthetic cost**
(`(0.004724 − 0.001745) / 0.004724 = 0.63`), on 16 cases. The routed policy's
quality gate is `pass` (delta 0.0). This is evidence for the *method* (declared,
evidence-gated, reversible routing), not a production cost claim.

### 2.4 Security & isolation

- The sandbox containment canary suite runs real hostile programs against the
  hardened runner (network exfiltration, host escape, privilege escalation,
  resource bombs, malicious artifacts, secret disclosure). Reproduce with
  `make sandbox-image && make sandbox`. Controls and their tests:
  [docs/security/sandbox.md](../security/sandbox.md),
  [docs/security/threat-model.md](../security/threat-model.md).
- Generated code runs only in an isolated boundary (Docker locally; microVM
  adapter for production) with a fixed protocol — no model-controlled image,
  mount, network, capability, or package (ADR-003).
- IaC (`infra/opentofu/`) passes `tofu validate` and Checkov with **zero
  failures** (14 justified inline skips). CI enforces CodeQL, Semgrep, Trivy,
  Gitleaks, zizmor, and pip-audit ([.github/workflows/security.yml](../../.github/workflows/security.yml)).

## 3. Honest limitations

- **Production deployment is a reference, not a live service.** The GCP
  OpenTofu modules and microVM sandbox adapter are reviewed and validated, but
  no hosted environment ships with this release. Local execution uses the Docker
  runner; production isolation requires wiring a microVM provider.
- **Default model backend is a deterministic `fake`.** It runs *real* generated
  code in the sandbox (so answers are genuinely computed), but it is not a cloud
  LLM. A real model requires configuring the OpenAI-compatible gateway; its
  quality is not claimed without eval evidence.
- **Numbers are from synthetic fixtures on a 16-case suite.** They illustrate
  the evaluation and accounting method, not production performance.
- **No compliance certification** (SOC 2 / HIPAA / GDPR) is claimed; see
  [SECURITY.md](../../SECURITY.md).
- One known local-dev quirk: on Windows, run the API in Docker rather than a bare
  `uvicorn` (async-Postgres event-loop policy). Documented in
  [local development](../operations/local-development.md).

Out-of-scope capabilities (by design) and the forward roadmap are in the
[README non-goals](../../README.md#non-goals--limitations) and
[docs/product/backlog.md](../product/backlog.md).

## 4. Reproduce it

```bash
# tests (see §2.1)
make check                     # ruff · mypy strict · import-linter · non-integration tests + gate
uv run pytest -m integration   # 78 passed (needs the compose stack)
uv run pytest -m sandbox       # 26 passed — agent computes real answers in the hardened runner
uv run pytest tests/security   # 31 passed — containment + authz (marked integration; select by path)

# evaluation gate (§2.2) and routing experiment (§2.3)
make sandbox-image
make eval-run                  # scores core suite vs frozen baseline, applies the gate
```

Committed example reports: [`evals/reports/examples/`](../../evals/reports/examples/).
